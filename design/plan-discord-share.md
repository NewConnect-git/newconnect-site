# 計画書：記事の公開時に Discord へ自動投稿

> この計画書は RieTamura リポジトリの `design/plan-discord-share.md` の写しです（2026-11-11）。NewConnect のサイトで使うので、これからはこちらを更新します（RieTamura 側は更新しません）。本文の「このサイト」「rietamura.com」などは、写した時点のまま rietamura.com を指しています。

作成日：2026-11-06

## 1. やりたいこと

EmDash で記事を公開すると、Discord のチャンネルに記事のカード（タイトル、リンク、アイキャッチ画像）を 1 回だけ自動で投稿する。

## 2. 決まっていること

| 項目 | 決定 |
| --- | --- |
| 作り方 | EmDash のプラグインを新しく作る（方法2）。RSS を読むボットは使わない |
| 送り先 | Discord の Webhook（チャンネルごとの URL）。ボットやログインは使わない |
| 作りの手本 | EmDash To Bluesky（`bluesky-share`）。重複を防ぐ仕組みと管理画面の作りをそろえる |
| Post To EmDash と Auto Thumbnail Design | 変えない |
| 投稿の中身 | カード（Embed）に、タイトル、リンク、抜粋、アイキャッチ画像。文面は管理画面で変数を使って変えられる（下の表） |
| カードの上の文 | 初期値は空（カードだけ）。変えたい人は管理画面で書ける |
| 対象 | 初期値はブログ記事（`posts`）だけ。管理画面で変えられる |
| 置き場所 | 最初から公開リポジトリ（例：`RieTamura/EmDash-To-Discord`）で作る |
| レジストリへの公開 | 本番で動いたあとで決める |

（2026-11-06 にユーザーと決めた）

## 3. 管理画面で変えられる文面

| 設定 | 初期値 | Discord の上限 |
| --- | --- | --- |
| カードの上の文（`content`） | 空 | 2000 文字 |
| カードのタイトル（`embeds[0].title`） | `{title}` | 256 文字 |
| カードの説明（`embeds[0].description`） | `{excerpt}` | 4096 文字 |
| アイキャッチ画像を付ける | 付ける | なし |

使える変数：

| 変数 | 中身 |
| --- | --- |
| `{title}` | 記事のタイトル |
| `{url}` | 記事の公開 URL |
| `{excerpt}` | 抜粋（空なら空） |
| `{date}` | 公開日（`YYYY-MM-DD`） |
| `{collection}` | コレクションの名前（`posts` など） |

- 上限を超えたら、末尾を切って「…」を付ける。
- 知らない変数（`{foo}` など）はそのまま残す。
- タイトルが空になったら `{title}` に戻す。カードのリンクはいつも記事の URL。
- 文面の中の `@everyone` やメンションは、`allowed_mentions` を空にするので通知しない。

## 4. 仕組み

```
記事を公開（Obsidian の Post To EmDash、または管理画面）
      │
      ▼
content:afterPublish（公開の処理のあとで動く）
      │  ① 対象のコレクションか、導入後に公開した記事かを確かめる
      │  ② 投稿の記録を先に作る（同じ記事の 2 回目はここで止まる）
      │  ③ Webhook の URL に、カードの JSON を 1 回送る
      ▼
Discord のチャンネルに投稿が出る
```

Bluesky ではログイン、画像の送信、投稿の 3 回の通信が要った。Discord は 1 回で済む。画像は Discord が記事の画像の URL から自分で取りに来るので、画像のデータを送らなくてよい。

送る内容の例：

```json
{
  "content": "",
  "embeds": [{
    "title": "記事のタイトル",
    "url": "https://rietamura.com/posts/...",
    "description": "抜粋",
    "image": { "url": "アイキャッチ画像の公開 URL" },
    "timestamp": "公開日時"
  }],
  "allowed_mentions": { "parse": [] }
}
```

送り先は `…/api/webhooks/<ID>/<トークン>?wait=true` にする。`wait=true` を付けると Discord が投稿の ID を返すので、記録に残して、管理画面から投稿を開けるようにする。

## 5. 誤投稿を防ぐ仕組み（bluesky-share と同じ）

| 場面 | 動き |
| --- | --- |
| 公開し直し、更新 | 記録があるので投稿しない |
| 導入前に公開した記事の更新 | `publishedAt` が導入時刻（kv の `state:since`）より前なので投稿しない |
| 翻訳 | 翻訳のグループで記録するので、日本語版と英語版で 1 回だけ |
| 未設定のとき | 「未送信」と記録する。あとから管理画面の「送る」で送れる |
| 失敗したとき | 「失敗」と記録する。自動では送り直さない。記事の公開は止まらない |
| 送りすぎ（Discord の 429） | 「失敗」と記録する。少し待ってから管理画面で送り直す |
| `@everyone` などが記事のタイトルにあったとき | `allowed_mentions` を空にするので、だれにも通知しない |

## 6. 安全面

- Webhook の URL は、知っている人がだれでもそのチャンネルに投稿できる「合言葉」。`secret` 設定で、`EMDASH_ENCRYPTION_KEY` で暗号化して保存する。ログとエラーのメモには URL を書かない。
- URL が漏れたときは、Discord で Webhook を消して作り直し、管理画面の設定を入れ替える。README に書く。
- 通信先は `discord.com` だけにする（`allowedHosts`）。設定に入れた URL が `https://discord.com/api/webhooks/` で始まらなければ送らない。
- 必要な権限は `content:read` と `network:request`。画像のデータは送らないので、`media:bytes:read` は要らない見込み。

## 8. 本番に入れる手順

1. Discord で、送りたいチャンネルの「チャンネルの編集 → 連携サービス → ウェブフック → 新しいウェブフック」で作り、URL をコピーする。名前とアイコンもここで決められる。
2. デプロイする。起動時に導入時刻が記録され、ここより前の記事は投稿されない。
3. 管理画面のプラグイン設定に、Webhook の URL を入れる。
4. テスト記事を 1 つ公開し、Discord のカード、画像、リンクを確かめる。
5. `wrangler tail` のログで、エラーがないことを見る。
6. テスト記事と Discord の投稿を消す。

## 9. 今後の候補

- 記事を消したときに、Discord の投稿も消す（記録した投稿の ID で消せる）。
- 記事を更新したときに、Discord の投稿も書き換える。
- 複数のチャンネルへ送る。
