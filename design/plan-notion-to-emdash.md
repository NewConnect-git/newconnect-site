# 計画書：Notion To EmDash（Notion のデータベースから記事を投稿する）

> この計画書は RieTamura リポジトリの `design/plan-notion-to-emdash.md` の写しです（2026-11-11）。NewConnect のサイトで使うので、これからはこちらを更新します（RieTamura 側は更新しません）。本文の「このサイト」「rietamura.com」などは、写した時点のまま rietamura.com を指しています。

作成日：2026-11-06

## 1. やりたいこと

- Notion のデータベースに書いた記事を、EmDash の `posts` に投稿する。
- 画像のない記事には、Auto Thumbnail Design のデザインでサムネイルを付ける（Post To EmDash と同じ見た目）。
- あとでほかの人も使えるように、公開リポジトリで配る。

## 2. 決まっていること

| 項目 | 決定 |
| --- | --- |
| 動かす場所 | サイトの外。GitHub Actions で定期的に動かす（2026-11-06 決定） |
| きっかけ | Notion の Webhook は使わない。決まった間隔で Notion のデータベースを見に行く（2026-11-06 決定）。Webhook には、インターネットから届く受け口が要るため。Cloudflare Worker で受けるとサムネイルを描けないので、中継用の Worker も必要になり、部品が増える |
| 投稿する記事 | 「公開」チェックボックスに印がある記事だけ。ページを作っただけでは送らない（作った直後はタイトルも本文も空のため） |
| サムネイル | 外のツールが Canvas で描く。サイトでは描かない（画像1枚に CPU 時間が 30〜150 ミリ秒かかり、Workers 無料プランの約10ミリ秒を超えるため。`plan-auto-thumbnail.md` を参照） |
| EmDash プラグインにしない理由 | プラグインのサンドボックスでは CPU が足りず、WebAssembly も使えないので、サムネイルを描けない |

## 3. 仕組み

```
Notion のデータベース（記事を書き、「公開」に印を付ける）
      │
      ▼
GitHub Actions（例：30分ごと）
      │  ① Notion API で「公開に印があり、まだ送っていない・送ったあとに直した」ページを探す
      │  ② 本文のブロックを読み、Portable Text に変える
      │  ③ 本文の画像を Notion から取ってきて、EmDash のメディアにアップロードする
      │  ④ アイキャッチも本文の画像もなければ、Auto Thumbnail Design の
      │     GET …/design と GET …/image を読み、1200×630 の PNG を描いてアップロードする
      │  ⑤ EmDash の REST API（/_emdash/api/…）で記事を作る・更新する
      │  ⑥ Notion のページに、送った印（EmDash の URL と送った日時）を書き込む
      ▼
EmDash のサイト（公開するとページのキャッシュが消える）
```

## 4. Notion のデータベースの項目（案）

| 項目名（案） | 種類 | 使い方 |
| --- | --- | --- |
| タイトル | タイトル | 記事のタイトル |
| 公開 | チェックボックス | 印があれば公開で送る |
| スラッグ | テキスト | URL の一部。空なら自動で作る |
| 抜粋 | テキスト | `excerpt` |
| カテゴリ | セレクト | `category` |
| タグ | マルチセレクト | `tag` |
| アイキャッチ | ファイル | あればこれを `featured_image` にする |
| EmDash URL | URL | ツールが書き込む。空なら「まだ送っていない」 |
| 送信日時 | 日付 | ツールが書き込む。送ったあとに人がページを直したら、送り直す（判定は6章） |

項目名は設定で変えられるようにする（ほかの人のデータベースにも合わせるため）。

## 6. 気をつけること

- **Notion の画像の URL は約1時間で使えなくなる**。そのまま記事に入れず、必ず取ってきて EmDash のメディアにアップロードする。
- **GitHub Actions の定期実行は、時間どおりに動くとは限らない**。混んでいると数分〜十数分遅れることがある。
- **公開リポジトリでは、60日間コミットがないと定期実行が自動で止まる**。止まったら GitHub の画面で有効に戻す。README にも書く。
- **GitHub Actions の無料枠**：公開リポジトリなら無料で無制限。非公開リポジトリは月 2,000 分までで、1回の実行は1分に切り上げて数える。15分ごとだと月 約2,900 回になり、枠を超える。非公開で使う人には30分ごと以上をすすめる。
- **合言葉の置き場所**：Notion のインテグレーションのトークンと EmDash の API トークンは、GitHub の Secrets に入れる。リポジトリのファイルには書かない。
- **Notion 側の準備**：インテグレーションを作り、データベースに「接続」を追加しないと読めない。手順を README に書く。
- **1回の件数**：1回に送る件数に上限を付ける（例：5件）。失敗した記事は、次の回にもう一度試す。
- **Notion API の版**：2025年に、データベースの読み方（data source）が変わった。作り始めるときに最新のドキュメントで確かめる。
- **送り直しの判定（2026-11-09）**：ツールが「送信日時」を書き込むと、ページの最終更新日時も新しくなる。また、最終更新日時は分単位に丸められることがある。そのため時刻は比べず、「最後に編集した人（`last_edited_by`）がツール自身でなければ、送ったあとに人が直した」と判定する。ツール自身の ID は `GET /v1/users/me` で取る。最後に編集した人が分からないときだけ時刻で比べる。書き戻しのあと本当にツールが最後の編集者になるかは、手順7で確かめる。
- **Notion で消した記事・印を外した記事**：最初は何もしない（サイトに残る）。必要になったら、下書きに戻す機能を足す。
- **EmDash のプラグインレジストリには出せない**：プラグインではなく、GitHub のツールとして配る。
